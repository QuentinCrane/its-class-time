# FRD｜功能规格与确定性规则

> 可据此直接拆开发任务。UI 上的文案可润色，但规则及行为必须保持一致。
>
> **这份文档回答**：时间怎么算、状态怎么判、编辑和通知在边界情况下必须怎么表现。它是两端引擎的唯一规则来源，与实现冲突时以本文为准，并同步修改 `shared/test-cases/time-engine.json`。

## 1. 时间语义（唯一规则源）

- 所有课程时段使用当前本地时区的**墙上时间 `HH:mm`**；在真实日期上转换成时间点做比较。
- 单日时段为 `[start,end)` 半开区间：08:00–08:45 在 08:45:00 已不属于第一节。
- V1 单个时段不得跨午夜；允许相邻、允许空档，**不允许重叠**；结束必须晚于开始。
- 时段类型：`focus`（上课/工作）、`break`（短课间）、`long_break`（长休息）、`lunch`（午休）。空白时间用引擎的 `idle` 状态表达，不要求自动插入记录。
- 课程序号只统计 `focus` 时段；休息不占“第 N 节”。
- 进度 `p = clamp((now - start)/(end - start),0,1)`；当前课时 `0≤p<1`，已结束的课时应显示 100%。休息同样有自己的时段进度，但不能误当成学习节数。
- 通过本地日期先选「仅今日覆盖」还是常规模板；无日程时显示 `idle`，不报上课事件。
- 日期变更、系统时间调整、时区更换、睡眠唤醒或编辑配置后，都**重新从当下真实时间定位**，不能靠 tick 累加保证正确性。
- V1 不要求支持跨日课程、跨午夜班次。若遇夏令时的不存在/重复本地时刻，应拒绝生成歧义时段或稳定选择一次并提示，不能触发两次通知。

## 2. 高中/大学模式

- 是两套用户可编辑的**初始化数据**，不是两种计时算法。
- `shared/presets/` 中放代表性样例：高中可用 45 分钟 + 10 分钟休息；大学可用 90 分钟大课 + 更长间隔。不得宣称是全国统一校铃。
- 用户可增删时段、改名、改起止、调整午休。编辑后形成用户模板，**不直接覆盖仓库内置预设文件**。
- 是否启用星期重复、某日休息由模板的 `activeWeekdays` 控制；今日覆盖只影响指定日期。

## 3. 双层编辑、数字输入和滑动条

### 3.1 编辑界面

- 每一行显示类型、名称、开始、结束、持续分钟数、更多操作。
- 使用系统原生时间选择器或 `HH:mm` 输入；另外提供一个 `整数分钟` 的数字框和一个**滑动条**用于调节持续时长。
- 数字框允许精确到 1 分钟；滑动条步进建议 5 分钟，适用范围由控件视角限定（普通课程如 5–180 分钟，午休如 5–240 分钟）。**范围仅限制滑动条，不限制合法的手动输入值**；超出滑块范围时以数字框为准，滑块显示边界值并提供明确提示，避免静默舍入。
- 编辑过程中滑动条和数字框显示一致的时长；拖动滑块更新结束时间；手输结束时间更新分钟数。所有修改先在草稿中预览，**保存时统一校验**。
- 编辑课时/午休不能隐式挤压重叠。出现冲突时提示，并让用户选择调整策略。
- Windows 时间轴可拖动时段整体或两端，按所选的 1、5 或 15 分钟步进调整；步进作用于拖动量，不舍入原始时间。冲突时取消本次调整，后续时段不自动移动；常规模板与今日计划分别保存。

### 3.2 保存策略

- **仅今天**：复制当天有效计划至 `dailyOverrides[YYYY-MM-DD]`，保存修改，不影响日常模板。
- **永久修改**：修改选中模板，按照该模板启用的星期重复；当天若已有今日覆盖，必须明确提示“今日仍按临时方案执行”，不要暗中覆盖。
- 修改时长若影响后续，用户可选：A. `shift`：将当前段之后的同日时段整体顺延变化分钟；B. `keep`：后续维持原位置。两者都必须验证有无重叠、越过 24:00；不合法就不保存，并指出冲突行。
- 当改变当前时段“开始时间”时，只按用户明确选择的值计算，不自动重新排列前面的时段。
- 修改生效后：作息状态、悬浮显示、下一事件时间**同步重算**；禁止马上补发修改前已经过去的事件。
- 仅今日覆盖过了对应日期后不再生效；可定期清除旧覆盖，避免无限增长。

## 4. 分节长条

- 默认主视图；每个 `focus` 显示独立小横条，过去填满、当前按百分比填充、未来空白。
- 课间可用短间隔或小型休息条表达，午休/长休息必须明显可辨；**视觉上不能把午休错绘为一节课**。
- Hover 显示课程名称、序号、开始/结束、已过/剩余分钟、进度百分比及下一时段预告。
- 不 hover 时显示最少信息，不持续闪烁；当前段明确突出。
- 浮窗支持拖动、吸附到显示器**可用工作区域的四条边**并记忆位置；顶部/底部为横向排列，左侧/右侧自动切换为竖向排列。适配 macOS 菜单栏/刘海、Windows 任务栏及不同 DPI。悬停卡向屏幕内侧展开，圆环在左右贴边时仍保持圆形，只改变停靠位置。
- Windows 可在「显示与位置」选择组件所在的显示器或跟随系统主显示器，不改变系统主屏；保存的显示器不可用时，组件定位回退到系统主屏。
- Windows 分节长条可调整沿贴边方向的总长度和背景色；恢复默认时沿用原有横向、竖向尺寸和系统背景。
- Windows 显示设置中的预览与真实有效作息、当前进度、系统配色和显示设置同步；组件细节和位置示意在调整时保持可见。预览中的屏幕位置按示意尺寸缩放，不改变提醒调度。
- **连续三击悬浮条或圆环**：沿当前所在边回到居中位置，不改变贴边方向；每次点击间隔不超过系统双击时间。若启用了贴边自动隐藏，三击展开后的主体同样生效。
- Windows 长条和圆环自动收起后，贴边把手按当前课程或休息时段的进度填充并着色。空档、未开始或当日结束时只显示底轨，鼠标靠近可展开主体。
- 贴边默认**无间距**：底部贴边时直接落在任务栏上沿，顶部/左右同理；长条的靠边一侧采用小圆角，中段与边缘对齐。用户可在显示设置关闭「紧贴边缘」，恢复 12 DIP 的悬浮间距。
- 时段颜色按类型区分：`focus` 使用系统强调色，`break` / `long_break` 使用休息色，`lunch` 使用暖黄色。单色进度视图跟随当前时段；全天分色边框同时显示各时段各自的颜色。
- 与常规应用窗口并存时尽量不激活/抢焦点；悬浮层可显式隐藏并经托盘/菜单栏恢复，不强制实现复杂的鼠标事件全穿透（它与 hover 冲突）。
- macOS 多 Space/全屏、Windows 独占全屏或系统界面可能限制置顶，**不可承诺总在所有窗口之上**。

## 5. 圆环视图

- 以“当前课程/当前休息时段”的进度作为最重要的读数，提供圆形进度；没有课程时给出未开始/空闲/已结束状态。
- 可选配展示相邻时段的小型圆环，但首版无须实现复杂的多环交互；优先一个明确的主环。
- 用户在长条与圆环之间切换不改变作息和通知状态。
- 低动效、支持系统减少动态效果、遵循高对比度。
- Windows 圆环采用独立圆形浮窗，圆心显示剩余时间，空档显示下一时段开始时间。悬停查看详细时段，全天范围下表盘补充当日已完成课节数。

### Windows 屏幕边框

- 「屏幕边框」是一种可选的矩形进度环，从左上角顺时针沿显示器工作区四边绘制，给任务栏留出空间。沿用悬浮窗记忆的显示器，无匹配显示器时使用主屏。
- 当前时段显示正在进行的课程或休息的进度，空档时仅显示底轨。全天显示从当日首段开始到末段结束的时间进度，包含中间空档。当天无安排时仅显示底轨。
- 全天默认按时段分色：沿边框顺时针按实际时长分配上课、课间、长休息和午休，空档保持中性色；已过部分颜色较深，未到部分较浅。颜色及进度深浅在相邻交界处平滑过渡，短时段自动缩短过渡范围。也可切换为原有的“跟随当前时段”配色，以当前类型为整段进度着色。
- 边框不接收鼠标输入，显示与隐藏由设置或托盘控制。
- Windows「显示与位置」使用横向分段按钮切换样式和范围；屏幕边框全天范围可选择分色方式。预览随选择和边框粗细即时更新。屏幕边框默认 10 DIP，可调至 4–24 DIP。

## 6. 显示范围：当前时段 / 全天

- **全天**：显示当天全部 `focus` 条，`break/long_break/lunch` 作为间隔或标志。空间不足时允许缩小/限制最小交互区域，并在悬停中准确标出每节，不能篡改时间长度或遗漏时段。
- **当前时段**：用于降低密度。以 `lunch` 或 `long_break` 为**显式分隔符**，各分隔符之间的 `focus + break` 构成连续“学习块”；短课间不拆块。
- 当前时刻属于某块 → 展示该块；处于午休/长休息 → 按时间顺序同时展示正在进行的休息和即将到来的下一块（若无下一块则展示上一块；仅有休息时展示休息），休息显示自己的进度与对应颜色；尚未开课 → 第一块；全部结束 → 最后一块并标注结束。
- 这只是**展示过滤**，通知与时间引擎永远基于全天完整有效日程。
- 圆环模式下的显示范围选择同样保留设置，但主环仍只展示当前事件；“全天”可用轻量辅助刻度呈现全天结构，不能强制展开一排圆环。

## 7. 通知：后台事件判断 → 官方即时通道

### 7.1 唯一方案

```text
同一个常驻应用进程
  ├─ 读取今天有效作息
  ├─ 计算下一边界并等待（非 1 秒忙轮询）
  ├─ 到点以系统真实时钟核验边界
  ├─ 检查免打扰开关、系统通知授权、事件去重
  └─ macOS: UNUserNotificationCenter (trigger: nil)
     Windows: AppNotificationManager.Show(AppNotification)
```

- **绝不预排整天通知**，程序常驻期间由程序自行判断事件并调用系统立即送达 API。
- 系统最终是否横幅展示由用户权限、焦点/勿扰模式、操作系统决定；应用不得模拟官方通知中心。
- 有上课/下课、课间、午休开始/结束等事件；具体显示策略统一通过通知设置开关决定。
- **一键暂停提醒**：`muted=true` 时进度持续，所有事件不发通知；恢复后不补发暂停期间错过的通知。
- 每个事件稳定唯一键 `localDate + segmentId + boundaryKind + effectivePlanRevision`。保存近期已触发键，防止同一边界因重新唤醒/重算重复发送。
- 正常运行如到点后因线程调度略有延迟，在允许的很短窗口内发送一次；建议触发容差 30 秒（实现时可配置成常量）。超过窗口或因启动/唤醒/重配产生的过期事件一律跳过。
- 休眠唤醒、重新打开应用、调时间、改变时区、刚保存模板后：重算下一个未来边界，**不发送旧事件**；不能连弹多条。
- UI 关闭/隐藏不影响进程继续检测；用户选择**退出应用**后不承诺继续提醒。

### 7.2 事件文案示例

| 事件 | 标题 | 内容 |
|---|---|---|
| focus_start | 开始啦 | 第 3 节开始了（10:00–10:45） |
| focus_end | 下课了 | 第 3 节结束，记得活动一下 |
| break_start | 课间休息 | 休息 10 分钟 |
| lunch_start | 午休时间 | 按今天的安排稍作休息 |
| lunch_end | 午休结束 | 接下来准备进入下午的安排 |

> 同一个边界若“第 3 节结束”和“课间开始”同时发生，**只展示一条合并通知**，避免刷屏。通知具体措辞可由设计调整，但去重规则不得变。

## 8. 进程/窗口/显示器

- 关闭设置窗口 != 退出；托盘/菜单栏中有明显的 `退出` 命令。
- 菜单至少包括：显示/隐藏、长条/圆环、当前时段/全天、暂停/恢复提醒、设置、退出。
- 启动时只运行一个主应用实例；第二次打开应该激活现有实例或显示设置，而不是创建两个独立计时/通知进程。
- 断开外接显示器/更换主屏/缩放后，将悬浮窗恢复到仍可见的工作区域；避免被甩到屏幕外。
- 开机登录启动为用户**可选**，不可悄悄写入启动项。

## 9. 推荐的最小本地状态结构

- 随应用只读捆绑的 `presets/*.json` 是**示例**，用户首次选中时复制到其可写配置。
- 用户配置：`schemaVersion`、`selectedTemplateId`、`templates`、`dailyOverrides`、`presentation`、`notifications`、`launchAtLogin`。
- 事件去重轻量数据可单独保存 `runtime-state.json`，避免用户配置频繁写盘。
- 配置采用原子写入（写临时文件后替换）；JSON 错误时保留故障原件并恢复安全默认设置，不能让应用因一条坏配置崩溃。
- 双端各自使用其系统推荐的应用数据目录；不要求用户手动创建文件夹。
- 仅 JSON 文件，无 SQLite/HTTP/RPC/账户系统。

## 10. 非功能与边界

- 进度应随时钟正确变化，不等于动画必须高帧率；后台采用下一边界等待，浮窗可低频更新绘制值，避免持续 60 FPS。
- 测试首次启动、睡眠 2 小时唤醒、跨日、切换时区、短时间系统时间调整、权限拒绝、双屏缩放、空白日程、多节紧邻等情况。
- 不将“不唤醒沉睡电脑”视为缺陷；不承诺覆盖独占全屏/系统安全屏幕。
- 时区/夏令时在 V1 要有稳定行为及边界测试，但不要求覆盖复杂跨日工作班次。
